# 按书源脚本权限管理 —— 设计与补全方案

> 状态：方案设计（未实施）
> 日期：2026-08-16
> 关联分支：test（工作区已有 UI 骨架改动）

## 一、目标与决策记录

为书源脚本（Rhino JS）提供按书源粒度的权限管理，控制 Cookie、Book 对象、Java/Android API、Toast 的访问。

已确认的设计决策：

| 决策点 | 结论 |
|---|---|
| 作用范围 | **按书源配置**（非全局），存储按 sourceKey 设计 |
| Book 权限 | 先**只存储不执行**，界面标注「暂未生效」 |
| API 开关语义 | **仅控制危险类清单**：编译期硬编码黑名单保持不变作为底线，开/关只影响各包的「可配置危险类清单」 |
| Toast 时长 | 选项式对话框：跟随脚本 / 强制短(2s) / 强制长(3.5s) / 自定义毫秒 |
| UI 入口 | **两个入口**：精确管理 → 权限管理（页内选源）；书源管理条目菜单直达 |
| 源类型 | 先只做**书源（BookSource）**，架构天然兼容将来扩展订阅源 |
| 默认值 | 全部允许，保证现有书源零影响 |

## 二、现状盘点（工作区已完成部分）

- 入口链路：精确管理页新增「权限管理」项（`pref_precise_manage.xml` + `PreciseManageFragment.kt`）→ `PermissionManageActivity`（已注册 `AndroidManifest.xml`）→ Compose 界面
- 界面骨架：`ui/permission/PermissionManageScreen.kt` 展示 5 个分区（Cookie / Book / Java API / 安卓 API / Toast）共 14 个权限项
- `ui/permission/PermissionSection.kt`：静态占位数据（注释已注明待替换为 ViewModel UiState）
- 四语言文案（values / values-zh / values-zh-rHK / values-zh-rTW）

**缺口：权限无持久化、无交互控件、无任何执行拦截。**

### 执行点核查结论（已逐一定位）

| 权限 | 拦截点 |
|---|---|
| Cookie 读/写/删 | 脚本经 3 条路径调用 `CookieStore`：绑定变量 `cookie`（`AnalyzeRule.kt:1052`、`AnalyzeUrl.kt:369`、`BaseSource.kt:347`）、`java.getCookie`（`JsExtensions.kt:413/418`）。**隐蔽旁路 2 个**：①`java.ajax` 请求隐式附带/回写 cookie（`AnalyzeUrl.kt:739` setCookie、响应自动保存）；②绑定变量 `cache` 可直接读写 `{domain}_cookie` 内存缓存项（`CacheManager`） |
| Book 读/改/删 | 脚本经绑定变量 `book`（`AnalyzeRule.kt:1055`、`AnalyzeUrl.kt:375`）拿到完全可变的 Book 实体；项目已有 `ReadOnlyJavaObject` 只读包装可复用（本轮不执行）。脚本本无删书 API——数据库访问已被 `RhinoClassShutter` 沙箱挡死（`io.legado.app.data.dao` 等在黑名单） |
| java.lang/io/net、android.content/net、系统信息 | `modules/rhino/.../RhinoClassShutter.kt:48-120` 为编译期硬编码黑名单，需改造为可按源动态注入 |
| Toast 开关/时长 | `JsExtensions.toast/longToast`（`:1094`/`:1114`）→ `ToastUtils.toastOnUi`，时长落点 `ToastUtils.kt:65`（自绘 View 的 Toast 支持自定义毫秒） |
| 系统信息补充点 | `JsExtensions.androidId()`（`:1199`） |

按源查权限的钥匙：`AnalyzeRule` / `AnalyzeUrl` / `BaseSource` 均持有 `source`，经 `getSource()?.getKey()` 查权限管理器。

## 三、实施方案（四个阶段，每阶段可独立编译验证）

### 阶段 1：数据层（存储 + 按源读写）

1. 新建 `app/src/main/java/io/legado/app/help/config/SourcePermission.kt`：
   - `data class SourcePermission`：14 项权限
     - `cookieRead / cookieWrite / cookieDelete`
     - `bookRead / bookModify / bookDelete`（本轮只存储）
     - `javaLang / javaIo / javaNet`
     - `androidContent / androidNet / androidSystem`
     - `toastEnabled`
     - `toastDurationMode`（0=跟随脚本 / 1=强制短 / 2=强制长 / 3=自定义）
     - `toastDurationCustomMs`
     - **默认全部允许**（Boolean 默认 true）
   - `object SourcePermissionManager`：内存缓存（ConcurrentHashMap）+ 读写；存储复用 `SourceConfig` 的 SharedPreferences（`SourceConfig.kt:10`），key 为 `perm_${sourceKey}`，值 JSON。按 sourceKey 存，将来扩展订阅源零成本。
2. 源删除时清理：`SourceHelp.kt:99` 已调 `SourceConfig.removeSource(key)`，在该方法内一并清除 `perm_` 前缀 key。

### 阶段 2：UI 改造（两个入口）

1. **权限页内选源**：`PermissionManageActivity` 改为双屏：
   - 新增书源列表屏（Compose LazyColumn：名称+地址+启用状态，带搜索框，数据来自 `appDb.bookSourceDao()`）；
   - 点某源进入单源权限编辑页 = 改造现有 `PermissionManageScreen`：接收 `sourceKey`，新增 `PermissionManageViewModel` 加载/保存 `SourcePermission`（替换 `PermissionSection.kt:37` 的静态占位数据）。
2. **每行加 Switch**：复用 `AppSettingSwitchItem` 样式风格（`ui/widget/components/settings/AppSettingItems.kt:17`），与现有图标行合并（图标+标题+描述+右侧开关，整行可点）。
3. **Toast 时长行**：点击弹对话框，单选「跟随脚本 / 强制短(2s) / 强制长(3.5s) / 自定义毫秒(数字输入)」。
4. **Book 三项**：可配置可保存，描述文案加「（暂未生效）」提示。
5. **书源管理菜单入口**：`res/menu/book_source_item.xml` 加「权限管理」项，在 `BookSourceActivity` 条目菜单点击处理中跳转 `PermissionManageActivity` 并传 `sourceKey` 直达编辑页。
6. 新增字符串（搜索提示、时长选项、暂未生效提示）补齐 4 个 locale；顺手修复 `values/strings.xml` 末尾缺换行。

### 阶段 3：执行层 —— Cookie / Toast / 系统信息（均在 app 模块）

1. **Cookie 读/写/删**：新建代理类 `PermissionCookieStore(perm) : CookieManagerInterface by CookieStore`，被禁操作抛出带书源标签的明确异常（调试可见）。注入/拦截点：
   - 3 个绑定点换成代理：`AnalyzeRule.kt:1052`、`AnalyzeUrl.kt:369`、`BaseSource.kt:347`；
   - `JsExtensions.getCookie`（`:413/:418`）加读权限检查；
   - ajax 隐式附带/回写 cookie（`AnalyzeUrl.kt:739`、响应自动保存）：被禁时**静默跳过**（不打断请求）；
   - `cache` 绑定旁路：新建 `PermissionCacheManager` 薄代理（手写委托 `CacheManager` 常用方法约 15 个），对 `_cookie` 结尾的 key 套用 cookie 权限，其余放行。
2. **Toast**：`JsExtensions.toast/longToast`——`toastEnabled` 关闭时静默不弹；时长按 mode 覆盖传给 `ToastUtils.toastOnUi` 的 duration。
3. **系统信息**：`JsExtensions.androidId()` 受 `androidSystem` 开关控制。

### 阶段 4：执行层 —— Java/Android 类访问（rhino 模块，仅危险类清单）

语义：硬编码黑名单（Runtime / ClassLoader / ProcessBuilder / java.io.File 等）**保持不变**作为应用安全底线；每个 API 开关额外管控一份「可配置危险类清单」，关闭时该清单对**该源脚本**生效。

1. app 侧定义 `ScriptClassPermissions`：6 个开关各自的危险类清单（示例，实施时可调整）：
   - java.lang → `System` / `Thread` / `ThreadGroup`（Runtime、ProcessBuilder 已在硬编码底线中）
   - java.io → 各 `Reader` / `Writer` / `Stream` 类（File、RandomAccessFile 等已在底线中）
   - java.net → `URL` / `HttpURLConnection` / `Socket` / `ServerSocket`
   - android.content → `ContentResolver` / `ContentValues`（Intent、Context 已在底线中）
   - android.net → `ConnectivityManager` / `WifiManager` / `Uri`
   - 系统信息 → `Build` / `Settings` / `SystemProperties` / `StatFs`
2. rhino 模块传递机制（避免 ThreadLocal 在协程切线程后失效）：
   - `ScriptBindings` 增加 `var securityPolicy` 属性；app 侧 3 个 evalJS 绑定点按源设置；
   - `RhinoScriptEngine.getRuntimeScope(bindings)`（`:251-262`）时把 policy 拷贝到 `RhinoContext`（新增 `var extraBlockedClasses`）；
   - `RhinoClassShutter.visibleToScripts(name)`（`:186`）在硬编码检查外追加 `(Context.getCurrentContext() as? RhinoContext)?.extraBlockedClasses` 检查；注意 `ClassNameMatcher` 的 LruCache（`ClassNameMatcher.kt:9`）对动态部分失效或单独缓存。
3. 不在范围内（保持现状）：`JsExtensions` 自带的 `readFile` / `deleteFile` / `getFile` 等文件 API，不属于本次 14 项权限模型。

## 四、验证

- 每阶段结束 `gradlew :app:assembleDebug` 编译。
- 阶段 3/4 完成后用调试书源手动验证：
  - 关 cookie 读 → `cookie.getCookie` / `java.getCookie` 报权限异常，且 ajax 不再附带 cookie；
  - 关 toast → 不弹；
  - 关 java.net → `importClass(java.net.Socket)` 被拒；
  - **默认全开 → 现有书源行为完全不变**（回归底线）。
- 提交前 `git status` 确认无遗漏文件；建议 `.zcode/` 加入 `.gitignore`。
