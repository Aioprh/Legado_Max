# 搜索框统一迁移计划：内联 `OutlinedTextField` → `AppSearchBar`

> 状态：**待执行**（`AppSearchBar` 已落地，文件管理界面已接入）
> 本文是 `feat(ui): 文件管理搜索栏抽取通用 AppSearchBar + 新增用其他文件管理器打开当前路径按钮` 的后续阶段计划。

---

## 1. 背景与目标

`AppSearchBar` 已抽取至 `ui/widget/components/`（跨 Feature 脚手架层），文件管理界面已接入并删除旧 `FileSearchBar`。

**目标**：把其余界面里**内联**的搜索框统一改用 `AppSearchBar`，消灭重复实现，收敛到一套对外稳定的搜索组件 API。

**范围**：以下 5 个界面（都是同一模式：`OutlinedTextField` + Search 图标 + Clear 按钮 + placeholder + 自定义 colors）：

| # | 界面 | 文件 |
|---|------|------|
| 1 | 书源回收站 | `app/src/main/java/io/legado/app/ui/source/recycle/SourceRecycleBinScreen.kt` |
| 2 | 阅读记录 | `app/src/main/java/io/legado/app/ui/book/readRecord/ReadRecordScreen.kt` |
| 3 | URL 记录 | `app/src/main/java/io/legado/app/ui/urlRecord/UrlRecordScreen.kt` |
| 4 | 调试日志 | `app/src/main/java/io/legado/app/ui/debuglog/DebugLogScreen.kt` |
| 5 | 封面分组 | `app/src/main/java/io/legado/app/ui/config/covergallery/CoverGalleryScreen.kt` |

> 另有 2 个精简版（`ui/main/homepage/manage/BrowseSourcesPage.kt`、`BrowseRssSourcesPage.kt`，无 Clear、无自定义 colors）可在同一次收尾时一并迁移，成本极低，本文末尾附注。

## 2. 现状：5 个界面各自内联

每个界面都在 `AnimatedVisibility(visible = showSearch)` 里直接写 `OutlinedTextField`，差异点：

| 界面 | query 类型 | hint | 清除动作 | 容器色 | 特殊项 |
|------|-----------|------|----------|--------|--------|
| 书源回收站 | `String?` `.orEmpty()` | `R.string.search` | 本地 `searchQuery = ""` | `surface` | 选择态时隐藏（`!isSelectionMode`） |
| 阅读记录 | `state.searchKey: String?` | `R.string.rr_search_books` | `viewModel.setSearchKey("")` | 局部变量 `searchFieldColor` | — |
| URL 记录 | 本地 `String` | **字面量** `"搜索URL/域名/来源"` | 本地 `searchQuery = ""` | 局部变量 `containerColor` | 下方另有 `FilterPanel`（不受影响） |
| 调试日志 | `searchQuery: String?` | **字面量** `"搜索日志内容..."` | `viewModel.setSearchQuery(null)` | 局部 `cardColor`/`secondaryTextColor`/`mutedIconTint` | **有 `keyboardActions(onSearch = …)` 回车即提交** |
| 封面分组 | 本地 `String` | **字面量** `"搜索分组"` | 本地 + `viewModel.setSearchQuery("")` | `elevatedContainerColor`/`pageAccentColor()` | — |

## 3. 目标态：全部改用 `AppSearchBar`

```kotlin
AnimatedVisibility(visible = showSearch) {
    AppSearchBar(
        query = ...,
        onQueryChange = { ... },
        hint = "...",
        onClear = { ... }   // 按需覆盖默认行为
    )
}
```

### 3.1 逐个迁移要点

**① 书源回收站**
- `query = searchQuery.orEmpty()`（ nullable → 非空，传 `?: ""`）
- `onQueryChange = { searchQuery = it }`
- `onClear = { searchQuery = "" }`
- `AnimatedVisibility` 条件保持 `visible = showSearch && !isSelectionMode` 不动
- 删除 `OutlinedTextFieldDefaults` 等 import

**② 阅读记录**
- `query = state.searchKey ?: ""`
- `onQueryChange = { viewModel.setSearchKey(it) }`
- `onClear = { viewModel.setSearchKey("") }`

**③ URL 记录**
- `query = searchQuery`
- `onQueryChange = { searchQuery = it }`
- `onClear = { searchQuery = "" }`
- 下方 `FilterPanel` 原样保留，不受影响
- hint 建议改为资源化（见 §4）

**④ 调试日志** ⚠️ 最特殊
- `query = searchQuery ?: ""`
- `onQueryChange = { viewModel.setSearchQuery(it.ifBlank { null }) }`
- `onClear = { viewModel.setSearchQuery(null) }`
- **回车提交行为**：当前 `keyboardActions(onSearch = { viewModel.setSearchQuery(searchQuery) })` 是功能（回车确认搜索）。需 `AppSearchBar` 增强支持（见 §4），否则迁移后回车不再触发搜索

**⑤ 封面分组**
- `query = searchQuery`
- `onQueryChange = { searchQuery = it; viewModel.setSearchQuery(it) }`
- `onClear = { searchQuery = ""; viewModel.setSearchQuery("") }`

## 4. 需要对 `AppSearchBar` 增强（1 处）

当前 `AppSearchBar` 的 `keyboardActions` 是空的 `onSearch = { }`。**调试日志**依赖回车提交，需新增可选参数：

```kotlin
@Composable
fun AppSearchBar(
    query: String,
    onQueryChange: (String) -> Unit,
    hint: String,
    modifier: Modifier = Modifier,
    showClearButton: Boolean = true,
    onClear: (() -> Unit)? = { onQueryChange("") },
    onSearch: (() -> Unit)? = null            // 新增：回车提交
) {
    ...
    keyboardActions = KeyboardActions(onSearch = { onSearch?.invoke() })
    ...
}
```

只此一处增强，5 个界面里只有调试日志需要传 `onSearch`，其余不传即可。

## 5. 外观权衡（需拍板）

`AppSearchBar` 是**圆角药丸样式**（`BasicTextField` + `RoundedCornerShape(8.dp)` + `pageCardContainerColor()`），无描边；5 个界面当前都是**带描边的 `OutlinedTextField`，且容器色各不相同**（`surface` / `searchFieldColor` / `containerColor` / `cardColor` / `elevatedContainerColor`）。

迁移后 5 个界面都会统一成药丸样式，**外观会有变化**。二选一：

- **方案 A（推荐，统一外观）**：全部迁成药丸 + `pageCardContainerColor()`。理由：与已落地的文件管理界面、`AppPageTopBar` 的视觉语言一致；5 个界面原本的容器色互相也不统一，收敛后更整齐；API 最简。
- **方案 B（保留外观）**：给 `AppSearchBar` 增加 `containerColor` / `borderColor` 参数，各界面传自己的颜色。代价：参数变多，且本质退化成 `OutlinedTextField` 的薄包装，"统一"的价值打折。

本计划按 **方案 A** 编写；如需方案 B，把 §4 的增强换成 `containerColor` 参数即可。

---

## 6. 顺带清理

- 3 个界面（URL 记录、调试日志、封面分组）的 hint 目前是**字符串字面量**，违反"字符串必须资源化"约定。迁移时一并抽到 `strings.xml`，或至少记为 TODO。
- 迁移后各界面多余的 import（`OutlinedTextFieldDefaults`、`TextFieldDefaults`、`Icons.Default.Clear` 若仅此处使用）按需清理。
