# 源编辑界面 Tab 切换性能优化计划

## 问题根因

书源编辑界面（BookSourceEditActivity）有 6 个 Tab，每个 Tab 对应一个 RecyclerView 列表，包含多个 CodeView 文本框。切换 Tab 时：

1. `setEditEntities()` 调用增量通知（`notifyItemRangeChanged/Inserted/Removed`）
2. 所有可见 item 的 ViewHolder 被 rebind
3. 每个 CodeView 在 bind 后调用 `requestHighlight()`，**500ms 后同时触发全文正则匹配 + span 操作**
4. **核心瓶颈**：所有可见 CodeView 同时执行 O(text_length × num_patterns) 的正则匹配和 span 创建/销毁，造成主线程卡顿

---

## P0-1：CodeView 高亮请求添加位置偏移延迟

**文件**: `app/src/main/java/io/legado/app/ui/widget/code/CodeView.kt` (第 291-294 行)

**现状**: 
```kotlin
fun requestHighlight() {
    cancelHighlighterRender()
    mUpdateHandler.postDelayed(mUpdateRunnable, mUpdateDelayTime.toLong())
}
```
所有 CodeView 统一使用固定 500ms 延迟，同时触发高亮。

**改法**: 
```kotlin
fun requestHighlight(position: Int = -1) {
    cancelHighlighterRender()
    val baseDelay = mUpdateDelayTime.toLong()
    val staggerDelay = if (position >= 0) position * 80L else 0L
    mUpdateHandler.postDelayed(mUpdateRunnable, baseDelay + staggerDelay)
}
```

**影响**:
- 正面：将同时触发的 N 个高亮任务错开到不同时间点执行。例如 6 个可见 item 分别在 500ms、580ms、660ms... 触发，分散到多帧中，避免帧率骤降
- 风险：无。仅改变高亮时机，不影响最终显示效果

## P1：setEditEntities 滚动前取消旧高亮

**文件**: `app/src/main/java/io/legado/app/ui/book/source/edit/BookSourceEditActivity.kt` (第 535-559 行)

**现状**: 切换 Tab 时，旧的 CodeView 可能仍有待执行的高亮任务，与新 Tab 的高亮任务叠加。

**改法**: 在 `setEditEntities` 开头遍历 RecyclerView 可见 ViewHolders，调用 `cancelHighlighterRender()`：
```kotlin
for (i in 0 until binding.recyclerView.childCount) {
    val holder = binding.recyclerView.getChildViewHolder(binding.recyclerView.getChildAt(i))
    if (holder is BookSourceEditAdapter.MyViewHolder) {
        holder.binding.editText.cancelHighlighterRender()
    }
}
```

**影响**:
- 正面：避免旧 Tab 的高亮任务在新 Tab 渲染后仍执行，浪费 CPU
- 风险：低。只取消待执行任务，不影响已显示的高亮

## P2：空内容跳过 highlight 检查优化

**文件**: `app/src/main/java/io/legado/app/ui/widget/code/CodeView.kt` (第 226-239 行)

**现状**: 
```kotlin
private fun highlight(editable: Editable): Editable {
    if (editable.length !in 1..4096) {
        return editable
    }
    // ...
}
```

**改法**: 增加空值/空白检查：
```kotlin
if (editable.isBlank()) return editable
```

**影响**:
- 正面：空字段（如很多未填写的规则）跳过 clearSpans + 正则匹配，减少无效开销
- 风险：无

## P3（可选）：高亮延迟时间动态调整

**文件**: `app/src/main/java/io/legado/app/ui/widget/code/CodeView.kt` (第 291-294 行)

**改法**: 根据文本长度动态调整延迟：
```kotlin
val dynamicDelay = when {
    editable.length < 100 -> 200L
    editable.length < 500 -> 400L
    else -> mUpdateDelayTime.toLong()
}
mUpdateHandler.postDelayed(mUpdateRunnable, dynamicDelay + staggerDelay)
```

**影响**:
- 正面：短规则更快看到高亮，长规则延后避免阻塞交互
- 风险：低

## 优先级总结

| 优先级 | 修改 | 预期收益 | 难度 |
|--------|------|----------|------|
| P0 | CodeView 高亮错峰调度 | 高 - 消除同时高亮的帧率骤降 | 低 |
| P0 | Adapter 传入 position | 高 - 配合 P0-1 生效 | 低 |
| P1 | setEditEntities 取消旧高亮 | 中 - 避免冗余高亮任务 | 低 |
| P2 | 空内容跳过 highlight | 中 - 减少空字段无效开销 | 低 |
| P3 | 动态延迟调整 | 低 - 优化短文本响应速度 | 低 |
